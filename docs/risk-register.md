# Risk Register - Configuration Drift Validator

This document catalogs identified project risks, their potential impact on production safety, and the implemented engineering mitigations.

| ID | Risk Description | Probability | Impact | Severity | Mitigation Strategy | Status |
| :---: | :--- | :---: | :---: | :---: | :--- | :---: |
| **R-01** | **False Positive Drift Detection**<br>Legitimate differences (e.g. `dev-db` vs `prod-db` or replica scaling) falsely flag warnings and block valid deployments. | Medium | Medium | Medium | Implemented **Environment-Aware Validation Policies** (`validation_policy.py`) that explicitly allow known legitimate environment patterns. | Mitigated |
| **R-02** | **False Negative / Missed Critical Drift**<br>Adversarial formatting (e.g. whitespace, quotes, disguised URLs) slips past simple string comparisons. | Medium | Critical | High | Implemented **Input Canonical Normalizer** (`normalizer.py`) that sanitizes quotes, booleans, numeric strings, and URI hostnames before evaluation. | Mitigated |
| **R-03** | **Secret Exposure / Credential Leakage**<br>Real passwords or API tokens accidentally stored in database, logs, or UI. | Low | Critical | High | Strict **Metadata-Only Schema**: System accepts and records only secret presence (`exists: true`), source, and rotation age. Zero raw secret values are ever ingested or stored. | Mitigated |
| **R-04** | **Unsafe or Corrupt Rollback**<br>Rolling back restores an incomplete or corrupted configuration version, breaking production. | Low | High | Medium | **Immutable Version Snapshots**: Configuration bundles are saved as immutable relational snapshots with foreign keys. Rollbacks explicitly clone/reactivate verified historical IDs. | Mitigated |
| **R-05** | **Malformed Configuration Files**<br>User uploads invalid YAML, broken JSON, or malformed `.env` lines causing backend crashes. | Medium | Medium | Medium | Robust **Pydantic Schemas and Safe Parsers**: All uploads pass through `yaml.safe_load`, `json.loads`, and regex line parsers with user-facing HTTP 400 error diagnostics. | Mitigated |
| **R-06** | **Runtime Container State Divergence**<br>Git repository looks correct, but live running container has drifted due to hot-patching or manual overrides. | Medium | High | High | **Runtime Snapshot Comparison Engine**: Continuously validates active container parameters against approved configuration baselines. | Mitigated |
| **R-07** | **Bypassed Peer Review**<br>A developer directly deploys dangerous configuration changes without senior review. | Medium | High | High | **Pre-Production Deployment Gate**: Production deployment endpoint automatically rejects requests if any CRITICAL issue is open, and high-impact changes mandate change request approval. | Mitigated |
| **R-08** | **Tampering or Untracked Modifications**<br>Changes are made without accountability, hindering incident post-mortems. | Low | Medium | Low | **Centralized Tamper-Evident Audit Ledger** (`audit.py`): Automatically logs timestamp, user, action, risk level, and change details for every single event. | Mitigated |
